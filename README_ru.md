GUI-приложение на PySide6 для отладки шины Modbus и разработки Modbus-устройств.
Работает с Modbus TCP и Modbus RTU через синхронные клиенты pymodbus;
вся Modbus-логика выполняется в отдельном потоке (QThread), GUI не блокируется.

## Возможности

- Несколько одновременных подключений во вкладках: каждая вкладка —
  независимая сессия со своим соединением, таблицей регистров, логом и
  сканером. Настройки всех вкладок сохраняются между запусками в
  `~/.modbus_connector/settings.json` (старые односессионные файлы настроек
  продолжают работать), а через меню File — в произвольный JSON-файл
  (и загружаются обратно).
- Типы подключения: TCP (host, port, timeout), RTU (порт, baudrate, parity
  и т.д.; RTU по умолчанию) и **RTU over TCP / RTU over UDP** для
  преобразователей RS-485↔Ethernet — всё настраивается в GUI.
- Таблица регистров: строки с именем, типом области (coils, discrete inputs,
  holding/input registers), адресом и количеством; чтение и запись значений.
  Enter в колонке «New value» отправляет команду записи, Ctrl+R (Cmd+R на macOS)
  читает текущую строку; вся таблица доступна с клавиатуры.
- Богатое отображение значений: форматы на строку (dec/hex/s16/u32/s32/f32/
  u64/s64/f64/ascii) с вариантами порядка байт (ABCD/CDAB/BADC/DCBA),
  масштабирование со смещением и единицами измерения; изменившееся при чтении
  значение на пару секунд подсвечивается.
- Unit ID на строку (разные строки — разные устройства на шине) и свой
  интервал поллинга на строку (медленные и быстрые регистры в одной таблице).
- Живые графики (кнопка «Graph…», отдельное окно): спарклайн-тренд у каждой
  строки таблицы и полноценный график с несколькими рядами, скользящим окном
  или ручным зумом и перетаскиваемыми маркерами с min/max/avg по рядам.
- Фоновое логирование опрашиваемых значений в файл CSV или JSON Lines
  (кнопка «Log to file») с настраиваемым набором полей.
- Тема System/Light/Dark (pyqtdarktheme) в меню View — графики, спарклайны,
  цвета статуса и подсветка следуют за темой.
- Фильтр по таблице и сортировка по адресу одной кнопкой.
- Продвинутые функции протокола: Mask Write Register (0x16), Read/Write
  Multiple Registers (0x17), Read Device Identification (0x2B) и диагностика
  последовательной линии (0x08) — через отдельные диалоги.
- Наблюдаемость канала: статистика транзакций в статус-баре (счётчик, ошибки
  с процентом, самый частый вид ошибки, среднее время ответа), человекочитаемые
  имена Modbus-исключений и живой индикатор соединения (зелёный = alive,
  оранжевый «(idle)» = канал простаивает или деградировал).
- Сканер адресов (кнопка «Scanner…», отдельное окно): перебор unit id в заданном
  диапазоне с настраиваемыми пробами, показывает устройства, ответившие хотя бы
  на одну пробу; двойной клик по найденному unit подставляет его в панель
  подключения. Второй режим сканирует адресное пространство регистров известного
  unit и перечисляет ответившие адреса.
- Панель лога внизу окна, скрывается кнопкой «Log»: человекочитаемые запросы и
  ответы, опционально сырые кадры шины в hex (чекбокс «Raw») и выгрузка всего
  лога в файл («Save…»).

- Python 3.11+
- `PySide6`, `pymodbus[serial]==3.6.9`

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
```

```bash
modbus-connector
# или
python -m modbus_connector
```

## Использование

### Подключение

1. Выберите тип соединения: **TCP** (host, port), **RTU** (порт, baudrate,
   биты данных, чётность, стоп-биты — RTU выбран по умолчанию; кнопка
   «Refresh» обновляет список портов) или **RTU over TCP** / **RTU over UDP**
   (host, port — RTU-кадры внутри сетевого сокета, для преобразователей
   RS-485↔Ethernet вроде USR или Elfin).
2. Укажите **Unit ID** целевого устройства (используется для всех операций с
   регистрами) и **Timeout** ответа.
3. Нажмите **Connect**. Пока соединение активно, поля настроек заблокированы;
   чтобы их изменить, нажмите **Disconnect**.

Индикатор рядом с кнопкой живой: зелёный — канал на связи, оранжевый с
пометкой «(idle)» — соединение настроено, но последняя транзакция завершилась
таймаутом; pymodbus прозрачно переподключается на следующем запросе, так что
это информация, а не ошибка. В статус-баре внизу окна — счётчики транзакций:
всего, ошибки с процентом и самый частый вид ошибки (полная разбивка по видам —
в подсказке к индикатору), а также среднее время успешных операций.
Modbus-исключения выводятся в лог по имени (например, «Illegal Data Address
(0x02)»).

### Работа со вкладками

Главное окно держит подключения во вкладках. Кнопка **+** в углу панели
вкладок открывает ещё одну независимую сессию — со своим соединением,
таблицей регистров, логом и окном сканера. Заголовок вкладки следует за
соединением (например, `tcp 192.168.1.10:502`); последнюю оставшуюся вкладку
закрыть нельзя. Статистика в статус-баре следует за активной вкладкой. Все
вкладки сохраняются в настройках при выходе и восстанавливаются при запуске —
включая ширины колонок каждой таблицы. Меню **View** переключает тему
(System/Light/Dark); выбор общий для приложения и сохраняется в настройках.

### Добавление регистров

Нажмите **Add register** и заполните строку: произвольное **Name**, **Type**
области (coils, discrete inputs, holding registers, input registers),
**Address** (десятичный или hex, например `0x10`) и **Count** (сколько
значений читать начиная с адреса). Необязательная колонка **Unit ID** переопределяет
unit из панели подключения для этой строки (пусто = использовать общий) —
удобно для опроса нескольких устройств на одной шине RS-485. Все колонки —
обычные ячейки, по таблице можно перемещаться с клавиатуры. Кнопка ✕ удаляет
строку.

### Чтение значений

- **Ctrl+R** (**Cmd+R** на macOS) — читает строку, на которой клавиатурный
  фокус; **Ctrl+Shift+R** читает все строки (кнопка «Read all»).
- Быстрые действия над текущей строкой (они же в контекстном меню таблицы):
  **Ctrl+C** копирует значение, **Ctrl+0**/**Ctrl+1** пишут 0/1,
  **Ctrl+=** (или **Ctrl++** на нампаде)/**Ctrl+-** шагают по последнему
  прочитанному значению, **Ctrl+T** переключает его (coil инвертирует бит; регистр — 0↔1). Запись
  идёт сырыми значениями, поэтому форматы со scaling/hex не мешают; для
  input/discrete областей выводится «read-only».
- **Read all** — читает все строки один раз.
- **Start polling and record** — split-кнопка: основное действие циклически
  читает все строки с интервалом из поля «Interval» (в миллисекундах) и
  записывает историю значений; остановка — **Stop polling**. В выпадающем
  меню — **Start polling** (без записи) и **Start polling and record**;
  выбор пункта во время поллинга переключает режим записи на лету, а
  последний выбор становится основным действием. Необязательная
  колонка **Poll, ms** переопределяет интервал для строки (пусто = глобальный
  интервал; меньшие значения фактически приравниваются к глобальному тику).

Прочитанные значения появляются в колонке **Value**; каждый запрос и ответ
также виден в панели лога (скрывается кнопкой «Log»). Контролы, работающие
с шиной (Read all, поллинг, логирование, диалоги 0x16/0x17, кнопки Start
сканера), доступны только при активном подключении — разрыв соединения
останавливает поллинг и логирование.

### Форматы, масштабирование и единицы

Для регистровых строк колонка **Format** задаёт вид значения в колонке Value:
`dec` (по умолчанию), `hex` (`0xNNNN`), `s16` (знаковое 16-бит),
`u32`/`s32`/`f32` (пара регистров как одно 32-битное значение),
`u64`/`s64`/`f64` (группа из четырёх регистров) и `ascii` (два символа на
регистр — имена устройств, серийные номера; строка обрывается на первом
NUL-байте). Coils и discrete inputs всегда показывают 0/1.

Многорегистровые значения по умолчанию big-endian (первый регистр — старшее
слово); комбо **Order** над таблицей задаёт порядок байт для всех строк
(`ABCD` по умолчанию, `CDAB` — слова переставлены, `BADC` — байты переставлены
в словах, `DCBA` — полный реверс), а переопределение для отдельной строки —
в диалоге **Display…**. Регистр, не заполняющий целую 32/64-битную группу,
показывается как есть.

Настройки **Scale**, **Offset**, **Unit** и per-row **Order** находятся в
диалоге **Display…** над таблицей (по строке на регистр). Сырые регистры
сначала декодируются согласно Format и Order, затем каждое число отображается
как `x * scale + offset` с дописанной единицей (например, `23.5 °C`). Для
форматов `hex` и `ascii` масштабирование не применяется. Ширина колонок
таблицы меняется перетаскиванием разделителей заголовка.

Изменившееся с прошлого чтения значение подсвечивается зелёным на ~2 секунды.

Поле **Filter…** над таблицей оставляет только строки, где имя, тип, адрес или
unit id содержат введённый текст; кнопка **Sort by address** физически
переупорядочивает таблицу по адресу.

### Запись значений

Введите значение(я) в колонку **New value** и нажмите **Enter** — команда
записи отправляется сразу. Значения всегда сырые: отображаемое масштабирование
(Scale/Offset) к ним не применяется.

- регистры: десятичные или hex-числа (`4321`, `0x10E1`); для Count > 1
  введите несколько значений через запятую или пробел (`1, 2, 0xFF`) — одно
  значение отправляется функцией «write single register», несколько —
  «write multiple registers»;
- coils: `0`/`1`, `true`/`false`, `on`/`off` (регистр букв не важен).

После успешной записи строка автоматически перечитывается, и колонка **Value**
показывает применённое значение. Ошибки разбора ввода и ошибки Modbus
выводятся в панель лога.

Важно: запись возможна только в coils и holding registers — discrete inputs и
input registers по протоколу доступны только для чтения.

### Продвинутые функции протокола

- **Mask write (0x16)…** (кнопка над таблицей) — Mask Write Register:
  AND/OR-маски к одному holding-регистру, установка или сброс отдельных битов
  без изменения остальных. После успешной записи строки, покрывающие адрес,
  перечитываются.
- **Read/Write (0x17)…** — Read/Write Multiple Registers: запись значений и
  чтение диапазона одной атомарной транзакцией (без окна гонки); прочитанные
  значения выводятся в лог.
- **Device ID…** (панель подключения, активна при подключении) — Read Device
  Identification (0x2B/0x0E): имя производителя, код продукта, ревизия и
  другие объекты устройства.
- **Diagnostics…** (панель подключения, активна при подключении) — диагностика
  последовательной линии (0x08): loopback-проверка эха и счётчики сообщений
  шины/устройства с кнопками Refresh и Clear counters. Функция
  последовательной линии, но некоторые TCP-устройства тоже на неё отвечают.

### Сканирование устройств

Нажмите **Scanner…**, чтобы открыть окно сканера. Задайте диапазон unit id
(по умолчанию 1–247) и список проб (тип регистра + адрес + количество,
которые пробуются на каждом адресе; разумные значения уже заполнены).
**Start scan** запускает обход, **Stop** — прерывает; адреса, ответившие хотя
бы на одну пробу, появляются в списке результатов. **Двойной клик** по
найденному unit подставляет его в поле Unit ID панели подключения. На время
сканирования поллинг в главном окне приостанавливается.

Секция **Registers scan** ниже работает наоборот: для известного unit она
по одному читает диапазон адресов выбранного типа регистров и перечисляет все
ответившие адреса в виде `0xNNNN (dec)` — быстрый способ составить карту
регистров незнакомого устройства.

Диапазон, список проб и параметры Registers scan сохраняются в настройках
вместе со всем остальным.

### Графики

Каждая строка регистров накапливает историю значений, пока идёт поллинг в
режиме «poll+record» (масштабированное инженерное значение; строки hex/ascii
пропускаются), и показывает её мини-графиком в колонке **Trend**. Буфер
ограничен ~10 тыс. отсчётов на строку; при выключенной записи спарклайны
и кривые графика замирают на последних данных. Кнопка **Graph…** (панель
подключения) открывает полноценное окно графика:

- чек-лист **Series** слева выбирает строки таблицы для построения (новые
  строки добавляются отмеченными);
- **X scale: Follow** ведёт скользящее окно заданной ширины за последними
  данными, **Full** вписывает всё, **Manual** замораживает вид — зум или пан
  (колесо у курсора, левый драг или тумблер **Zoom rect**) переключают режим
  в Manual, чтобы смена была видна; **Reset view** возвращает Follow;
- **Markers** показывает две перетаскиваемые вертикальные линии (зелёную A,
  красную B) и таблицу с min/max/avg каждого ряда между ними плюс Δt,
  обновляется на лету;
- при наведении курсора на график показывается кроссхейр: пунктирная
  вертикаль во времени курсора и значения всех рядов в этот момент в правом
  верхнем углу (ближайший записанный отсчёт, отмечен точкой на кривой);
- **Clear** очищает записанную историю и перезапускает ось относительного
  времени (маркеры размещаются заново при появлении новых данных); то же
  «Clear history» доступно в контекстном меню ячейки колонки Trend;
- **Start polling and record** дублирует кнопку поллинга таблицы: запускает
  поллинг с записью (или просто включает запись, если поллинг уже идёт),
  а при активной записи превращается в **Stop polling**.

Закрытие окна графика лишь скрывает его; данные сохраняются.

### Логирование значений в файл

Кнопка **Log to file** над таблицей пишет каждое прочитанное значение в файл,
пока включена; её запуск также запускает поллинг, если он не шёл (с записью
истории, если режим split-кнопки — «and record»). Кнопка **⚙** рядом
открывает настройки: файл (предлагается имя с меткой времени в домашнем
каталоге), формат, набор необязательных полей рядом со значением — метка
времени (настенные часы, ISO 8601 с миллисекундами), имя строки, адрес и тип
регистра — и выбор логируемых строк таблицы (чек-лист «Rows to log»; новые
строки логируются по умолчанию, выбор по строкам сохраняется с сессией).
Значения машиночитаемые: декодированные числа со scale/offset, но
без единиц измерения; несколько значений — через «;», coils/discrete — как
0/1, строки hex/ascii — как отображаются.

Форматы: **CSV** (строка на чтение, заголовок в новых файлах) и **JSON
Lines** — по JSON-объекту на строку, удобно для потоковой обработки и
дописывания. По умолчанию файл дополняется; настройки (но не состояние
вкл/выкл) сохраняются с сессией. Остановка логирования не останавливает
поллинг.

### Панель лога

Панель лога внизу главного окна (скрывается кнопкой **Log**) показывает все
запросы и ответы с метками времени. Чекбокс **Raw** дополнительно выводит
сырые кадры шины в hex (`→ tx …` / `← rx …`) — по умолчанию выключен, чтобы
лог оставался читаемым. **Save…** выгружает весь лог (включая скрытые
чекбоксом raw-кадры) в текстовый файл; **Clear** очищает его.

### Импорт/экспорт CSV

Выпадающая кнопка **CSV** над таблицей обменивается таблицей регистров с
табличными редакторами:

- **Import table…** загружает CSV-файл и *заменяет* всю таблицу. Сначала
  открывается диалог сопоставления: каждую колонку файла можно сопоставить
  полю регистра (name, kind, address, count, unit_id, poll_ms, format,
  scale, offset, unit, order) или пропустить; совпадения угадываются по
  именам колонок («type» считается kind), обязательные поля name/kind/address
  должны быть сопоставлены. Ошибки выводятся в лог, невалидный файл не
  трогает таблицу.
- **Export…** сначала открывает выбор колонок — отметить нужные и изменить
  их порядок (стрелки/Space/Ctrl+Up/Ctrl+Down) — затем пишет CSV: выбранные
  колонки плюс необязательную `value` с текущим отображаемым
  (отформатированным) текстом — читается как отчёт и импортируется обратно:
  колонка `value` в диалоге сопоставления по умолчанию пропускается, так что
  круг «export → правка в Excel → import» работает из коробки.

При импорте обязательны только `name`, `kind` и `address` — несопоставленные
необязательные поля заменяются значениями по умолчанию. Файлы пишутся в
UTF-8 с BOM, чтобы Excel открывал их корректно.


## Сборка исполняемого файла

```bash
./build.sh        # macOS / Linux
build.bat         # Windows (cmd, работает и двойным кликом)
```

Скрипт ставит PyInstaller (extra `build`) и собирает standalone-приложение в
`dist/`: на macOS — `ModbusConnector.app` + установочный образ
`ModbusConnector.dmg`, на Windows/Linux — каталог `ModbusConnector/` с
исполняемым файлом внутри (на Windows — `ModbusConnector.exe`; на другую машину
копируется весь каталог). Артефакт не требует установленного Python на целевой
машине.

Заметки для macOS:

- Запуск: двойной клик по `ModbusConnector.app` или `open dist/ModbusConnector.app`.
  Файлы из промежуточного каталога `build/` запускать нельзя (скрипт удаляет его
  после сборки).
- Для переноса на другую машину используйте готовый `dist/ModbusConnector.dmg`
  (самостоятельно переименовывать или упаковывать `.app` в `.pkg` не нужно —
  такой файл не будет валидным установщиком).
- Приложение подписано ad-hoc: при первом запуске на другом Mac Gatekeeper
  предупредит о неустановленном разработчике — открывайте через правый клик →
  «Открыть» или снимите карантин: `xattr -dr com.apple.quarantine ModbusConnector.app`.

Заметки для Linux:

- Для подключения по RTU к последовательным портам (`/dev/ttyUSB*`,
  `/dev/ttyACM*` и т.д.) пользователь должен состоять в группе порта, обычно
  `dialout` (иногда `uucp`). Если при подключении появляется `Errno 13` /
  «Отказано в доступе», проверьте порт:
  ```bash
  ls -l /dev/ttyUSB0
  ```
  Добавьте пользователя в группу и перезайдите в систему (или выполните
  `newgrp dialout`):
  ```bash
  sudo usermod -aG dialout $USER
  ```

## Структура проекта

```

  models.py       # типы данных и хелперы без Qt: TcpParams/RtuParams/
                  # RtuOverTcpParams/RtuOverUdpParams, RegisterRow, ScanProbe,
                  # DisplayFormat, ByteOrder, describe_connection(),
                  # parse_values()/format_values(),

                  # EXCEPTION_CODES/describe_exception(), Stats/StatsSnapshot

                  # чтение/запись, mask write (0x16), read/write registers
                  # (0x17), идентификация устройства (0x2B), диагностика (0x08),
                  # скан unit-адресов, скан адресов регистров, хук трафика
  worker.py       # ModbusWorker (QObject) — сигналы/слоты над backend, QThread;
                  # статистика времени, проверки живости, проброс трафика
  connection_panel.py  # панель подключения (TCP/RTU/RTU over TCP/RTU over UDP,
                       # state/set_state) с живым индикатором статуса
                       # (серый/зелёный/оранжевый); диалоги Device ID…/
                       # Diagnostics…
  registers_panel.py   # таблица регистров: unit/poll/формат/order/масштаб на
                       # строку, подсветка изменений, фильтр/сортировка,
                       # Enter = запись, диалоги Mask write…/Read/Write…
  scanner_panel.py     # сканер unit-адресов + скан адресов регистров
                       # (отдельное окно)
  log_panel.py         # панель лога (скрываемая): чекбокс Raw с hex-кадрами,
                       # Save…
  settings_store.py    # сохранение настроек в ~/.modbus_connector/settings.json

  main_window.py  # главное окно: сессии во вкладках, меню File,

  app.py          # создание QApplication и запуск
  __main__.py     # python -m modbus_connector
tests/
```

Тесты backend поднимают реальный Modbus TCP сервер (pymodbus) на 127.0.0.1

## CI

GitHub Actions (`.github/workflows/build.yml`) на каждый пуш в `main` гоняет
тесты и собирает артефакты под три ОС на раннерах macOS/Windows/Linux:
`modbus-connector-macos` (DMG), `modbus-connector-windows` и
`modbus-connector-linux` (zip с исполняемым файлом). Готовые файлы скачиваются
со страницы запуска workflow (Actions → выбранный run → Artifacts; хранятся
90 дней); сборку также можно запустить вручную через «Run workflow».

При пуше тега `v*` (например, `git tag v0.1.0 && git push origin v0.1.0`)
те же файлы автоматически прикрепляются к GitHub Release — постоянной странице
скачивания (Releases в репозитории).
